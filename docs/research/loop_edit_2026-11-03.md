# Loop-drift edits: can Ouro run past its trained depth? (2026-11-03)

Question: chain v3 (trained with 4 loops) is flat at 5–6 loops and collapses at 8 on NESTful
(.492/.483/.500/.192 at 4/5/6/8 on [0, 240)). Is the collapse a drift of the recurrent state that
an edit between loops can remove, and does removing it let 8 loops beat 4? Inspired by a report of
directional ablation fixing looping in Qwen3.5-0.8B (weight-space programming blog; unverified,
not cited). Code: `scripts/lab/loop_edit.py` (`EditedOuro` reproduces Ouro's forward exactly,
max abs logit difference 0.0 at 4 and 8 loops; edits apply only after loop 4, so depths <= 4 are
unchanged by construction).

## Development results (150 clean MathQA-val first prompts; 100 to find directions, 50 to screen)

* Drift of the state from its loop-4 value grows steadily: relative norm .14/.22/.30/.38 at loops
  5–8 (cosine to loop 4 .99 → .92). Along the loop-4 draft, loop 8's argmax differs from loop 4's
  on 1.3% of tokens (function names 7.7%, numbers 3.7%, JSON/markup 0.8%).
* The drift is not one direction: the top principal component explains 9%, the top 4 22%, the top
  16 39%; the mean drift is 18% of the drift norm. Unlike the Qwen report, there is no single
  failure direction.
* Screen (teacher-forced 8-loop pass over prompt + loop-4 draft, held-out 50 prompts; share of
  tokens whose loop-8 argmax differs from loop 4's, structure / function name / number):
  none .010/.08/.068; project top-1 PC .005/.08/.051; top-4 .003/.08/.064; top-16 .002/.09/.064;
  contrast direction .006/.08/.077; mean direction .007/.10/.073; damp β=.5 .000/.01/.034;
  damp β=.25 .000/.00/.013. Projecting out the top 16 drift directions removes most structural
  changes (the collapse signature) while leaving loops 5–8 free to change decision tokens;
  damping suppresses all change (it approaches 4 loops).
* Caveat: the teacher-forced first turn shows little corruption even unedited; the dialogue
  collapse builds up in free generation and later turns, so the screen is a weak proxy.

## Pre-registered test (2026-11-03, before any edited dialogue run)

Variants chosen on development data only: `project_pc16` (selected) and `damp_0.5` (direction-free
control). Data: chain v3 greedy multi-turn NESTful [0, 240) at 8 loops with each edit
(`router_smoke.py --tasks nestful --n 240 --depths 8 --modes greedy --edit <v> --tag
nestful_edit_<v>`), compared on the same requests with the existing unedited rows (d4 .492, d8
.192; tags `nestful`, `nestful_deep`).

* Primary (repair): accuracy at 8 loops with `project_pc16` minus unedited 8 loops, paired
  bootstrap 90% interval over requests: REPAIRED if the lower bound > 0.
* Secondary (extrapolation): `project_pc16` at 8 loops minus 4 loops (does 8 loops beat 4?),
  same interval; `damp_0.5` for both comparisons; tool errors per dialogue and unfinished share.
* Reading rules: repair without exceeding 4 loops = the collapse is removable but extra loops add
  nothing for this model; exceeding 4 loops = an extrapolation result worth confirming on unseen
  requests [720, 960); no repair = the collapse is not a low-dimensional drift.

## Result (job 729f0dde, 2026-11-03)

| 8 loops, NESTful [0, 240) | Accuracy | Tool errors / dialogue | Unfinished |
|---|---|---|---|
| 4 loops (reference) | .492 | .00 | .04 |
| 8 loops, unedited | .192 | 1.81 | .10 |
| 8 loops, project out top-16 drift | .375 | .24 | .05 |
| 8 loops, damp drift β = .5 | .496 | .00 | .03 |

Primary: REPAIRED (+.183, 90% CI +.138 to +.234). Secondary: the projection stays below 4 loops
(−.117); damping equals 4 loops (+.004, CI −.017 to +.029). The collapse is state drift and is
removable, but it is spread across many directions (the top 16 recover about 60% of the loss, as
the PCA suggested), and the best repair only gets back to 4-loop accuracy at twice the compute.
Following the reading rules: the collapse is removable but extra loops add nothing for this model.
